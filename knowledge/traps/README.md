# Knowledge traps (host-agent guardrails)

Short, high-signal notes for patterns where a **generic coding agent** reliably
botches undergrad EE work. Each trap has an id (T1, T2, …) tracked in
`docs/planning/eec301-lift/TRAP_CATALOG.md`.

Format:

- **Symptom** — what the bare agent produces
- **Why it fails** — physics or procedure
- **Arc path** — skill, engine, or eval to use instead

Do not paste entire lab PDFs here; link planning docs and kernel helpers.
